## Описание

Консольное приложение на C++, которое держит в памяти актуальную копию биржевого стакана Binance по выбранному инструменту и раз в секунду печатает лучшие цены и объёмы на покупку и продажу.

Данные берутся из двух источников:

- **REST API Binance** — для получения снапшота стакана и параметров инструмента.
- **WebSocket Binance** — для непрерывного потока изменений стакана в реальном времени.

Цены и объёмы хранятся как целые числа, умноженные на множители, полученные из `tickSize` и `stepSize` конкретного инструмента — это позволяет избежать потерь точности `double`.

---

 ## Как работает

1. **Определение параметров инструмента.**  
   Через `GET /api/v3/exchangeInfo` загружаются `tickSize` (шаг цены) и `stepSize` (шаг объёма). Из них вычисляются множители для перевода цен и объёмов в целочисленный вид.

2. **Запуск WebSocket-потока.**  
   Отдельный поток подключается к `wss://stream.binance.com:9443/ws/<symbol>@depth@100ms` и начинает принимать дельты стакана (`depthUpdate`).

3. **Буферизация событий.**  
   Пока не готов снапшот, все входящие WebSocket-события складываются в буфер.

4. **Загрузка снапшота.**  
   Через `GET /api/v3/depth` получается текущее состояние стакана и `lastUpdateId`.

5. **Синхронизация буфера.**  
   Снапшот инициализирует стакан, после чего буфер сливается по правилам Binance:
   - события с `u <= lastUpdateId` пропускаются;
   - первое валидное событие должно удовлетворять `U <= lastUpdateId + 1 <= u`;
   - при обнаружении разрыва запрашивается новый снапшот.

6. **Live-режим.**  
   После синхронизации каждое WebSocket-событие применяется к стакану сразу. Раз в секунду главный поток печатает лучшие bid/ask.

7. **Автовосстановление.**  
   Если в рантайме возникает разрыв `updateId`, программа сама перезапрашивает снапшот и продолжает работу.

## Установка зависимостей

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install -y cmake g++ \
    libboost-system-dev libboost-thread-dev \
    libssl-dev libcurl4-openssl-dev \
    nlohmann-json3-dev libwebsocketpp-dev
```

cpr из исходников:

```bash
git clone https://github.com/libcpr/cpr.git && cd cpr && mkdir build && cd build
cmake .. -DCPR_USE_SYSTEM_CURL=ON
make && sudo make install
```
Fedora / RHEL / CentOS

```bash
sudo dnf install -y cmake gcc-c++ \
    boost-devel openssl-devel libcurl-devel \
    nlohmann-json-devel websocketpp-devel
```

Arch Linux

```bash
sudo pacman -S cmake gcc boost openssl nlohmann-json websocketpp curl
```
cpr из AUR:

```bash
yay -S cpr
```
Или собрать из исходников.

```bash
g++ -std=c++17 -pthread \
    main.cpp OrderBook.cpp OrderBookClient.cpp TradingSystem.cpp \
    -o main \
    -lcpr -lboost_system -lssl -lcrypto
```

## Потоки

В программе работают два потока.

Основной поток выполняет всю стартовую логику и главный цикл вывода:

Парсит аргументы командной строки.

Делает rest запрос и вычисляет множители.

Создаёт OrderBook и объект websocket_endpoint — в этот момент порождается фоновый поток.

Регистрирует обработчик сообщений WebSocket.

Даёт команду на подключение к WebSocket.

Ждёт 500 мс, чтобы соединение успело установиться и пошли первые события (они уходят в буфер).

Запрашивает REST-снапшот и делает первичную синхронизацию.

Входит в главный цикл: раз в секунду берёт текущие best bid/ask и выводит их в консоль.

Фоновый поток (WebSocket) создаётся один раз в конструкторе websocket_endpoint и работает всё время жизни программы. Он обслуживает сетевой event loop Asio: устанавливает TLS-соединение, открывает WebSocket, принимает входящие сообщения и для каждого вызывает msg_handler. Пока снапшот не готов — события складываются в буфер, после готовности — сразу применяются к стакану.

Оба потока работают с общими данными, поэтому синхронизируются через мьютексы. Переключение между режимами «буфер» и «live» происходит по снапшоту, а актуальность WebSocket-потока контролируется сверкой updateId последнего применённого события — при обнаружении разрыва программа запрашивает новый снапшот.
